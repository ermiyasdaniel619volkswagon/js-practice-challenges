# Beginner JavaScript Practice Challenges 🚀

Welcome to the **Beginner JavaScript Practice Challenges** repository! 🎉

This project is designed for **beginner group students** who learn JavaScript through **hands-on daily challenges**, not by studying theory. The focus is on **thinking in steps (algorithms)** and solving problems that grow from **small to big**.

---

## 📌 Project Purpose

This project is **not about learning JavaScript theory**.

Instead, students learn JavaScript by **solving small challenges step by step using algorithms**.

We focus on **three core things**:

### 1️⃣ One HTML File

- `index.html` is the **one and only HTML page**
- It is used only to **run JavaScript files**
- All results are viewed in the **browser console**
- Uncomment only one script tag at a time to view the output in the browser console.

### 2️⃣ Multiple JavaScript Files (Code)

- Each challenge has its **own JavaScript file**
- Example: `fizzbuzz.js`
- Every `.js` file contains the **solution code** for one specific problem

### 3️⃣ Problem Description Files (Text)

- For every JavaScript file, there is a **matching `.txt` file**
- Example: `fizzbuzz.txt`
- This file explains:
  - The **problem statement**
  - The **algorithm** (step-by-step logic to solve the problem)

## 🛠️ Clone the Repository (Step-by-Step)


```bash
cd js-practice-challenges
```

---

## ▶️ How to Use the Project (Step-by-Step)

### 1️⃣ Open the Project Folder

```bash
cd js-practice-challenges
```

Open the folder in **VS Code** or any code editor.

---

### 2️⃣ Read the Problem First

- Go to the `problem/` folder
- Open the `.txt` file (example: `fizzbuzz.txt`)
- Read:
  - The problem
  - The algorithm steps

---

### 3️⃣ Write or Review the Code

- Go to the `code/` folder
- Open the matching `.js` file
- Write or review the JavaScript solution based on the algorithm

---

### 4️⃣ Run the Code

- Open `code/index.html` in a browser
- Open **Developer Tools → Console**
- View the output using `console.log()`

## 👥 How We Work (Daily Challenge Style)

- We solve **one challenge per day**
- We work **together as a group**
- No rushing, no pressure
- If students have extra time:
  - Improve the solution
  - Try a harder version of the same problem

-----------------Additional thing you must know!-------------------
👨‍💻 Contributor: How to Send Changes

Phase 1: Get the repo you want to fork

Fork: Click the "Fork" button on GitHub. (Now you have your own copy online).
Clone: Copy the code to your computer.
git clone <your-url>
cd <folder-name>

Phase 2: Do the Work

Branch: Create a "side room" to work in so you don't mess up the main code.
git checkout -b my-work
Save: Once you've typed your code, save it.
git add .
git commit -m "Fixed the header"

Phase 3: Send it Back
Push: Upload your work from your computer back to GitHub.
git push origin my-work (git push --set-upstream origin mywork)
PR: Go to GitHub and click the big green "Compare & pull request" button to ask the owner to look at your work.

👑 Owner: How to Merge the Work

1. Review
   The owner gets a notification. They go to the "Pull requests" tab in their repository and click on your PR to see what you changed.

2. The Big Green Button
   If the code looks good, the owner scrolls to the bottom. They will see a big green button that says: "Merge pull request"

3. Confirm
   They click "Confirm merge".

✅ Result: Your code is now officially part of their "Main" project!
